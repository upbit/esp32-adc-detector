# ESP32-C5 信源星盘 V1：给开发 AI 的实现要求

## 1. 任务

请实现一个可以在 ESP32-C5、MPU6050、320×320 SPI IPS 液晶屏上运行的单屏原型。视觉参考是已确认三联概念图的中间「02 弧带扫描」画面，仅还原这一个页面。

本轮重点：设备转动时星盘正确反向旋转；历史采样稳定留在相对起始坐标系中；液晶显示流畅、清晰；一个锁定 Wi-Fi 信源的真实 RSSI 能叠加到星盘。先把可观察、可调试的效果做出来。

交付可编译的设备端实现、配置说明、接线配置项、烧录与调试步骤，以及模拟数据预览或设备运行记录。不要只交网页或静态图片。若无法接触实机，明确区分编译验证、模拟验证和待实机验证项目。

## 2. 范围与硬件

| 项目 | 本版要求 |
|---|---|
| 主控 | ESP32-C5；优先沿用已有项目技术栈，空项目优先采用支持 C5 的稳定版 ESP-IDF |
| 姿态模块 | MPU6050，I²C，读取三轴陀螺仪与加速度 |
| 屏幕 | 用户实际可见区域 320×320，IPS，转接板标称 ST7796，SPI 写入 |
| 显示接口 | MOSI、SCK、CS、DC；另有 GND、3V3、BL；未标记引脚不使用 |
| 页面 | 只有「选中信源后的星盘扫描」 |
| 信源 | 第一版锁定一个 Wi-Fi AP，持续观察该 AP 发出的 Beacon RSSI |
| 调试入口 | 编译配置或串口命令即可；不依赖触摸，暂时不增加实体按钮 |

暂不实现完整信源列表、BLE、寻近第三屏、距离估算、地图、极坐标强度柱、自动定位、复杂菜单。

硬件接口说明：

- 屏幕 SPI 的 MOSI/SCK/CS 是数据与时序，DC 区分命令和数据，BL 为背光相关引脚。BL 的电路形式、有效电平必须按实际转接板确认，不能直接假定为 LED 电源或某一种控制极性。
- 以实际模块的初始化序列、可见窗口、旋转与颜色顺序为准。ST7796 名称不等于可以忽略 320×320 可见窗口的地址偏移；禁止盲目用别的分辨率初始化再拉伸画面。
- 将所有 GPIO、显示旋转、X/Y 偏移、RGB/BGR、背光极性、IMU 安装方向集中配置。已接好的 GPIO 优先沿用；没有接线信息时给明确待填项，不猜测已确认接线。
- 接线尽量按屏幕一侧、MPU6050 一侧分组，方便装配。具体 GPIO 需核对开发板型号、启动脚和存储器占用。

## 3. 必须还原的视觉

### 3.1 风格与层次

深海军蓝背景，青色作为实时扫描主色，琥珀色强调本轮最佳方向，灰蓝色表示历史。像精致的手持无线电仪表：克制、清楚、有星盘感。

信息优先级：天线朝向与扫描弧 > 当前 RSSI > 信源名称和频率 > 转角 > 调试信息。

参考色值可微调以适应 RGB565：

| 元素 | 建议色值 |
|---|---|
| 背景 | #04121E |
| 网格 | #25445B，低亮度 |
| 主文字 | #E7F2F8 |
| 次文字 | #9AB5C9 |
| 实时青色 | #25DFED |
| 暗青色 | #146173 |
| 强峰琥珀色 | #FFC45A |
| 历史灰蓝色 | #647283 |

中文嵌入必要字符的精简字库；数字采用清晰字体，RSSI 数字宽度保持稳定以免抖动。不要依赖电脑上的系统字体。

### 3.2 布局：逻辑坐标 320×320

原点为左上角，X 向右，Y 向下。以下是落地布局基准，可做数像素调整以避免裁切或重叠。

| 区域 | 坐标或尺寸建议 | 内容 |
|---|---|---|
| 信源名称 | x=12，y=10，最大宽 175，字高约 20 | 示例 CAM_02，真实模式替换为锁定 AP 的 SSID/别名，过长省略 |
| 频率 | x=12，y=38，字高约 14 | 示例 2437 MHz，真实模式从主信道计算 |
| RSSI | 右对齐到 x=308，y=10 | -61 用约 27 px 字体，dBm 用约 12 px 字体 |
| RSSI 小趋势线 | x=218，y=44，w=88，h=14 | 最近几秒的实际强度变化，缺测不伪造更新 |
| 天线标签 | 水平中心 x=160，y≈50 | 天线，约 13 px |
| 天线三角 | 顶点约 (160,64)，底边约 y=75 | 固定朝上，青色 |
| 星盘中心 | C=(160,170) | 青色小圆点，约半径 3 px |
| 星盘外圈 | R≈98 px | 细轮廓、角度刻度 |
| 历史/采样圈 | R≈88 px | 全部信号点位于同一固定半径 |
| 内部网格 | R≈25、49、74 px | 低亮度虚线同心圆与细十字线 |
| 左右角标 | 左侧 -90°，右侧 +90°，y≈162 | 外圈旁边，约 13 px |
| 底部角标 | 中心 x=160，y≈272 | 180° |
| 转角读数 | 中心 x=160，y≈230 | 转角 +030°，数字用青色 |
| 扫描进度 | x=67，y≈292，w=186，h=4 | 已真实采样方向覆盖比例 |
| 底部提示 | 水平居中，y≈303，字高约 14 | 慢速转动设备 |

屏幕不显示概念稿的外部装饰边框、大标题「信源星盘」或「02 弧带扫描」说明文字。

### 3.3 天线与扫描弧

- 天线三角、从中心指向屏幕顶部的细青色射线固定朝上；可加约 ±10° 的低亮度扇形光带。
- 射线表示设备当前朝向。它不自己绕圈，也不作与真实转动无关的雷达扫光。
- 本轮最近采样用青色弧带；相邻有效采样可以连成柔和曲线，少量小圆点保留真实采样感。
- 所有信号标记保持同一固定半径；RSSI 只影响弧带亮度和约 2～7 px 的厚度，不通过点位远近表示信号或距离。
- 保留平滑连续的观感，但只连接相邻、实际测量的方向。未扫描方向留空；禁止跨越大段缺测补一圈完整弧。
- 一版可使用 36 个角度桶，每桶 10°。不把这个分桶大小宣称为设备方向精度。
- 本轮稳定最强方向用一个琥珀色短弧标记，可以覆盖约 10°～20°；不要显示多个争抢注意力的强峰，不宣称精确信源方向。
- 强峰短弧随历史盘一起旋转，不能永远固定在顶部。用户把它转到顶部才表示天线对准该记录方向。
- Glow 用两三层低亮度描边近似，避免昂贵模糊或复杂粒子。

### 3.4 历史渐隐

初始建议值，集中配置：

| 距离最近一次实际采样的时间 | 显示 |
|---|---|
| 0～2 秒 | 明亮青色 |
| 2～8 秒 | 平滑淡成暗青色 |
| 8～20 秒 | 逐渐变成灰蓝色细弧 |
| 20 秒以后 | 低亮度细弧或短刻度，保留到本轮重置 |

新数据到达才刷新对应方向的时间戳。颜色淡化不能改变保存的 RSSI，也不能被理解为强度下降。历史限制在扫描圈附近，不从中心画多条穿盘灰线。本轮最多保留一个灰色历史最佳方向提示，其他历史弱化。

## 4. 转动逻辑：本版最重要的正确性要求

### 4.1 坐标约定

启动校准完成后，当前设备朝向设为 0°。只用相对偏航角，不显示 N/E/S/W，不把 MPU6050 当绝对指南针。

规定用户从上方看设备，顺时针水平转动为正角度。安装轴与符号必须可配置，实际确认传感器方向。

对于一个采样：

```text
sample.heading = 采样时设备相对起始方向的角度
screen_angle = wrap180(sample.heading - display_heading)

x = Cx + R * sin(screen_angle)
y = Cy - R * cos(screen_angle)
```

sin/cos 计算前转换为弧度。数据保存在相对起始坐标系，绘制时才减去当前朝向。

必须满足：

- 初始采样朝向为 0°时，点显示在顶部。
- 设备顺时针转 +30° 后，旧的 0° 点显示在顶部左侧约 30°。
- 此时新收到的 +30° 采样显示在顶部附近。
- 设备逆时针转动时，历史盘向相反方向旋转。
- 跨过 0°/360° 或 +180°/-180° 时无闪跳、无整圈回转。

内部积分使用连续展开角度，显示时再归一化。角度平滑不能直接对 359° 和 1°做普通算术平均。

### 4.2 MPU6050 要求

- 开机提示「静置校准」，先做约 2～3 秒静止零偏估计；检测到转动则延后，不能边转边错误校准。
- 建议姿态采集约 100 Hz，选择合适陀螺仪量程与低通配置；量程、安装轴、符号集中配置。
- 根据单调时钟的真实 dt 积分，不硬编码每次循环都是 10 ms。
- 一版测试姿势是设备尽量保持水平，绕重力方向转动。可读取倾斜角，在明显倾斜时提示「保持水平」。不要求本版解决任意三维姿态下的高精度航向。
- 不能写「加速度计或六轴 DMP 可自动消除 yaw 漂移」。没有额外航向参考时，相对偏航会累积漂移。
- 测量用 heading 与显示用 display_heading 分开。显示可用约 80～120 ms 的平滑；原始测量时间和角度不能被显示缓动覆盖。
- 静止时可以用可靠静止检测辅助零偏更新；不要用大死区粗暴抹掉慢速转动，也不要用 RSSI 强峰反推修正 IMU 朝向。
- 提供串口「重新置零」和「重新校准」入口。重新置零时清空扫描数据、峰值和进度，避免坐标系改变后历史错位。

### 4.3 信号与角度同步

IMU 和 Wi-Fi 数据使用同一设备单调时钟。保留短姿态历史；在 Wi-Fi 回调入口记录接收事件时间，将该读数关联到这个时刻的测量姿态，而不是 UI 绘制时的姿态。

这是软件事件时间对齐，不能宣称具有未经验证的射频硬件时间精度。回调到姿态查询的延迟与数据年龄应能在日志中观察。

显示和测量可以不同频率：Wi-Fi 来一包记录一次，UI 每帧根据当前朝向重绘历史。没有新 Wi-Fi 包，盘仍随 IMU 转动，但不生成新信号样本。

## 5. 一个 Wi-Fi 的锁定与 RSSI

### 5.1 最简选择路径

不制作第一屏信源列表。支持下列其中一条完整可用路径即可，优先配置方式：

1. 配置目标 SSID，可选目标 BSSID，启动扫描一次，确定 BSSID、主信道和频段后锁定。
2. 串口输出一次扫描结果，用户通过串口选择一项，进入星盘。

同名 SSID 必须确定到具体 BSSID。未指定 BSSID 时可以启动时选择信号最强的同名 AP，但之后不能自动切换 AP；在日志输出最终 BSSID 和信道。

锁定表示持续被动观察一个发射端，不要求输入密码或关联上网。第一版用会发送 Beacon 的 AP 作为测试对象；不能把目标 AP 的 RSSI 当成其下某个摄像头/手机客户端的 RSSI。

### 5.2 真实数据

- 锁定后固定到目标频段和频道，持续接收目标 AP 的 Beacon，按发射端地址/BSSID过滤，避免混入其他设备。
- 不用全频段循环扫描作为主要 RSSI 刷新机制。读取同类帧更方便进行强度比较。
- 正确解析帧类型、长度和地址，避免无效包、其他发射端数据污染方向桶。
- Wi-Fi 回调只做轻量取值和入队；统计、峰值判定和绘制在应用任务中处理，不能在驱动回调刷新 SPI 屏幕。
- 频率展示真实主信道中心频率，例：2.4 GHz CH6 → 2437 MHz。兼顾 CH14 特例与合法 5 GHz 信道映射；不得始终硬编码 2437 MHz。
- 顶部 RSSI 可用短窗口中位数配轻度平滑。方向桶则只统计该桶内实际样本，不能把跨方向的时间平均值写入一个桶。
- 每桶保存样本数、稳健 RSSI、更新时间；峰值至少经过多个有效包确认，不直接采用一次原始尖峰。
- 初始视觉映射可设为 -90～-40 dBm，超界钳位；这只是 UI 映射，不是接收器量程或距离。参数可调。
- 扫描进度 = 本轮实际收到目标有效样本的不同角度桶数量 / 36；原地收到很多包不能增长覆盖率，不要求扫满才显示。
- 超过约 2 秒没有有效包，显示「等待信号」或数据年龄提示，并将当前读数弱化；不能填入 0 dBm、假装信号变强或继续生成数据。
- 信源消失时保留历史；重新收到同一目标的数据再继续。不要自动换成其他 AP。

## 6. 必备模拟模式：方便优先调试屏幕与 IMU

分别配置姿态来源和信号来源：

| 模式 | 姿态来源 | RSSI 来源 | 用途 |
|---|---|---|---|
| UI_SIM | 自动旋转或串口设置角度 | 合成信号 | 不接 IMU/Wi-Fi，也能验证坐标与渲染 |
| IMU_SIM_RSSI | 真 MPU6050 | 合成信号 | 优先调试设备转动与星盘关系 |
| LIVE_WIFI | 真 MPU6050 | 锁定 AP 的真实包 | 联调真实扫描 |

合成示例：

```text
固定虚拟强峰方向 peak_heading = +60°
delta = wrap180(sample_heading - peak_heading)
rssi = -80 + 30 * exp(-(delta * delta) / (2 * 25 * 25))
每约 100 ms 生成一个样本
```

模拟峰值固定在起始坐标系，不能随设备朝向移动。转到 +60° 时最强约 -50 dBm，其他方向较弱。可加约 ±1 dB 小噪声，亦应有无噪声确定性模式。

模拟模式必须明确标注「模拟」；真实模式 IMU 失效时显示错误，不能悄悄改成模拟姿态。可以串口切换模式、设置模拟角度、清空本轮、重新置零，命令有帮助说明。

## 7. 刷新、内存与工程约束

- 姿态采集、包接收、统计和 UI 渲染解耦。UI 读取一致快照，历史容器有界，避免队列无限增长。
- 目标 UI 20～30 FPS，优先无闪烁与正确转动；以实测 SPI 带宽和运行堆内存为准，必要时降低刷新率并报告实测结果。
- 初始化先做屏幕颜色块、四角边界、文本方向检查，确认 320×320 可见区域、偏移和 RGB/BGR。
- 不在每帧可见地「清黑屏—逐条重画」。使用合适的局部刷新、分块缓冲或有内存预算的离屏渲染。
- RGB565 的整屏缓冲为 320×320×2 = 204800 字节，双缓冲约 409600 字节。不能在未确认 PSRAM、Wi-Fi 开销与剩余堆空间时默认整屏双缓冲。
- 推荐从小块行缓冲或局部画布着手，静态文字低频更新，星盘区域按需刷新。是否使用 LVGL 由现有项目决定，不为使用框架强行重写。
- 不在渲染循环反复创建对象或分配大量内存。三角函数、字形、刻度位置可预计算或缓存。
- 测量时间戳与显示动画统一采用单调时钟；不要因网络或 UI 卡顿造成积分 dt 异常后仍继续误积分。
- 记录错误状态：IMU 不可用、校准中、目标未发现、等待信号。主页面布局保持一致，避免错误时整屏空白。

## 8. 验收清单

1. 上电静置完成校准后，仅显示「02 弧带扫描」单屏；天线固定朝上，名称、MHz、RSSI 清楚可读，四边无裁切。
2. UI_SIM：0° 采样在顶部，设备角设为 +30° 后旧点向左转 30°，新点在顶部；+180°/-180° 边界连续。
3. IMU_SIM_RSSI：真实设备顺/逆时针转动，历史盘反向跟随；虚拟 +60° 强峰在转到该方向时位于顶部。
4. 停止生成信号样本后，历史盘仍随 IMU 旋转，历史颜色按时间淡化；空白方向不被补满。
5. 姿态保持不动时点位不跳跃；慢速转动能被识别。测量并记录 60 秒静止漂移，不承诺 MPU6050 零漂移。
6. 相邻有效方向可连接成弧；缺测方向不连接；没有中心交叉的历史灰线。
7. LIVE_WIFI：锁定到唯一 BSSID 和频道，RSSI 来自目标发射端；串口输出可验证过滤和样本数。
8. 模拟或真实的单包尖峰不会立刻夺走稳定强峰；峰值短弧会随设备转动，不能固定在顶部。
9. 真信源停止发送/关闭后显示等待信号，数值不会变成 0 dBm；恢复后继续同一目标。
10. 清空或重新置零后，历史、峰值、覆盖进度同步重置；校准时转动设备会阻止错误校准。
11. 连续运行 10 分钟，记录 FPS、可用/最低堆内存、包处理数量和异常；界面无明显闪屏，无持续内存增长。

上述是实施方需执行并报告的验收要求，不代表本要求稿已经完成设备端测试。
