## 范围与设计依据

本实现依据 `星盘UI_V1_AI实现要求.md` 的第 3、4、5、6、7 节及 `UI_Design.png` 中间页面，不新增列表、BLE、距离、自动航向修正或按钮。当前模块边界、矩形时序和DMA所有权状态机以[还原计划第4节](starchart-ui-reconstruction-plan.md#4-架构与接口草案)的 Mermaid 图为准；测量语义不变。

| 文件 | 责任 |
|---|---|
| `include/starchart_config.h` | 已知接线、待确认屏幕参数、IMU 轴、AP、模式和视觉参数 |
| `src/chart_hardware.c` | ST7796 SPI、MPU6050 I2C、Wi-Fi 扫描与 Beacon 回调 |
| `src/starchart.c` | 连续角度积分、姿态历史插值、桶中位数、单峰、覆盖与重置 |
| `src/starchart_render.c` | 纯变化覆盖与紧密矩形 RGB565 绘制，与主机整帧参考共用几何/字体 |
| `src/main.c` | 独立姿态、统计、显示、串口任务；快照、脏格合并、成功显示基准、双区调度与日志 |

姿态约 100 Hz，Wi-Fi 回调入口使用 `esp_timer_get_time()`，等待下一条姿态观测后按事件时间插值；绝不采用显示缓动角度写入方向桶。超出历史、跨越采集停顿或旧坐标系的事件被拒绝。日志 `event_age_max` 表示入口到应用处理的最大年龄，`data_age` 是最新有效包年龄。这是软件事件时间对齐，不是射频硬件同步。

桶内只存该方向最近五包的 RSSI、采样角度、中位数、累计包数与最新时间。强峰至少三包确认，切换需超出可配置滞回。36 桶表示覆盖分辨率，不是方向精度。RSSI 只改变固定 R=103 上的亮度与厚度。仅相邻已采样桶连弧，空白桶不会填满。渲染时间只改变历史颜色与线宽，不改保存 RSSI。

## 接线与屏幕确认

沿用 README：屏幕左侧 MOSI=8、SCK=6、CS=10、DC=9；MPU6050 右侧 SDA=4、SCL=5（2026-10-17 用户确认改接），AD0 接地、地址 0x68，VCC 共用 3V3，INT 不使用。核对实际开发板和模块输入电压；I2C 推荐模块已有或外接适当上拉，不依赖弱内部上拉实现高速通信。

用户已确认屏幕接线，BL 已连接 GPIO0；按本轮要求不调整背光，`CHART_LCD_BL=-1` 仍不驱动，未标记引脚不使用。不能把 GPIO 当 LED 电源。

ST7796 目前采用软件复位、退出睡眠、RGB565、MADCTL、反色、开显示的保守 DCS 初始化候选序列。P1/P2 已在此屏获得视觉反馈；尚未取得 TK015F4000 转接板厂商电源/gamma 初始化表，不能由此保证80 MHz像素可靠性。

**80 MHz 像素的移位预补偿**：ST7796 规格写周期下限为 66 ns（约 15 MHz），80 MHz 的 12.5 ns 周期超规格 5 倍以上，数据建立时间 T_SDS=10 ns 只剩约 2.5 ns 余量。实测面板晚一个位周期开始采样，像素流整体循环左移 1 位（背景 0x0083→0x0106 亮度翻倍、琥珀 0xFE2B→0xFC57 偏粉）。`CHART_LCD_SHIFT_BITS` 在像素流前补等量哑位抵消。**补偿按窗口而非按块**：窗口内 CS 保持，面板看到一条连续比特流，若每块独立补偿会在每个块边界再推 7 位并出现周期性色带；因此块之间接续进位，只有末块发出那个尾字节，整窗口只多 1 B。40 MHz 下自动停用。该偏移量对温度、供电和面板批次敏感，`CHART_LCD_SHIFT_DIAGNOSTIC=1` 叠加位标尺（第 k 块只置第 k 位，0x0000/0xFFFF 刻度为旋转不动点）与五色卡用于复核；跨温度长期稳定性未验收，40 MHz 为已知可用退路。若出现初始化问题，先取得模块资料并确认方案，不擅用其他屏控制器。

默认不显示检查图。显式编译 `CHART_LCD_BOOT_DIAGNOSTIC=1` 后，检查图以40 MHz经生产矩形接口发送，保持5秒再进入80 MHz星盘；`CHART_LCD_MIRROR_X=1` 校正已报告的左右镜像。检查图从左到右为铺满全高的红、绿、蓝、白色条，四边黑色1 px边界，四角TL/TR/BL/BR，中央数字与中文。保持期间 `health fps=0` 是预期行为；`test pattern sent over SPI` 只说明发送成功，没有屏幕应答或光学确认。诊断失败仅停止显示，未知DMA所有权不复用；不新增诊断按钮或命令。检查步骤：

1. 核对供电、SPI 接线；无独立 RESET，先使用软件复位。
2. 确认四边完整，核对 `CHART_LCD_X_OFFSET/Y_OFFSET`（当前0/0）。逻辑屏幕为320x320，发送窗口是其中的矩形，不做320x480拉伸。
3. 红蓝互换时切换 `CHART_LCD_BGR`；异常底色检查 `CHART_LCD_INVERT`。
4. 左右镜像检查 `CHART_LCD_MIRROR_X`；旋转方向错误时调整 `CHART_LCD_ROTATION`，并重新测偏移。
5. 对照同一星盘路径时，可将 `CHART_LCD_FAST_SPI_HZ` 设为40000000；诊断页本来就使用40 MHz。命令速率由 `CHART_LCD_SPI_HZ` 控制。实际流畅度结合更新间隔、`health fps` 与目视撕裂检查判断。

启动时一次分配两个最大320×32行DMA区，总40960 B、固定间隔20480 B；当前调度按不超过16行分块，最宽块10240 B，小于查询的12276 B事务上限。另有当前快照、上次成功显示状态（主机ABI分别7256/7272 B）、50 B mask及有界统计，运行时内存以日志为准。每轮无动态分配，不先擦可见屏、不分配整屏缓存；姿态、趋势和命令队列容量有界。

SPI保留两个长期描述符、深度2队列和匹配完成后回收；CPU序像素在提交内交换一次，1～4字节命令/参数内联轮询。每矩形独立打开、排空、关闭，N在途期间可在空闲区绘制N+1首块，但不能提前发N+1命令或跨帧预生成。全部窗口成功才提交显示快照，失败后停止显示且保留未知所有权像素，采集任务不停止。

每约5秒输出 `lcd: dirty`：实际更新数/FPS、空闲轮次、平均字节/窗口、draw/swap/cmd/dma_span/wait、总工作、堆/最低堆/栈和间隔粗直方图。`dma_span`含重叠绘制，`pending_draw`只证明描述符未回收，不能将两者相加或把差额当作实机节省时间。P50/P95为桶上界，17代表>=16 ms溢出桶；`dirty budgets`单列首次/整体失效和普通差异轮。目标约120 FPS，仍需设备实测，不保证无撕裂。

## 模式与串口

串口输入一行命令后发送换行，`help` 显示完整帮助。

| 命令 | 行为 |
|---|---|
| `mode imu` | IMU_SIM_RSSI（默认）：真实 MPU6050，合成信号固定峰 0°（校准时的初始朝向，琥珀标记即原方向，用于目视检查漂移） |
| `mode live` | LIVE_WIFI：真实 MPU6050、一次扫描确定 BSSID、固定频段频道接收 Beacon |
| `signal on` / `signal off` | 开关合成包；对 LIVE_WIFI 无效，不伪造真实读数 |
| `clear` | 清历史、峰值、RSSI 窗口、趋势、进度，保留相对朝向 |
| `zero` | 同步清空并设当前朝向为 0°，保留已估计陀螺零偏 |
| `cal` | 重试 IMU 初始化，清空，重新静置校准 |
| `imu` | 转储原始陀螺/加速度（dps/g）与投影偏航率，用于确认安装方向 |
| `stats` | 测量/显示角度、倾斜、桶数、包数、对齐拒绝与延迟、校准状态与失败原因 |

已移除：`mode ui`、`angle <deg>`、`auto on/off`——固件不再有合成姿态路径；真实 IMU 不可读时显示红色错误屏而不是模拟转动。`UI_SIM` 枚举仅保留给主机测试工具（`tools/`、`test/`）驱动渲染回归，固件构建不会进入该模式。

模式切换和重校准会清空本轮，不保留跨坐标系数据。真实/合成事件带来源标记，旧队列数据不能混入新模式。真实 IMU 失败显示「IMU 错误」，不会悄悄模拟。校准或长采集停顿时显示「静置校准」，停顿后重校准以避免未知 dt 误积分。

## IMU 调试与上电校准

上电/RST 后进入校准引导：屏幕中心画一个由实测重力水平分量驱动的气泡，目标位置是圆心 (160,156)。气泡进入圆心 10 px（约 17° 倾角，屏上画出目标圈）内且保持静止时，倒计时环绕中心顺时针填充，剩余秒数显示在转角位置；3 秒满后运行校验门，全部通过才将当前朝向设为 0° 进入星盘。

校验门逐项检查（任一不通过即拒绝并重新引导）：

| 检查项 | 阈值（`starchart_config.h`） | 屏幕提示 |
|---|---|---|
| 静止窗口中断（转动/晃动） | 陀螺偏离本窗口均值 ≥ 3.0 dps 或 |a|−1|g| ≥ 0.04 | `KEEP STILL` |
| 倾斜 | 倾角 ≥ 20° | `LEVEL DEVICE` |
| 陀螺噪声 | 逐轴方差 ≥ 1.5 dps² | `TOO MUCH NOISE` |
| 零偏幅值 | 任一轴 |bias| ≥ 5 dps | `GYRO BIAS HIGH` |
| 重力不可信 | |a| ∉ [0.85, 1.15] g 或上轴分量 < 0.9 | `BAD GRAVITY` |

静止判定以窗口均值为基准而非 0：实机 MPU6050 静置零偏为 −2.43, −0.89, −0.71 dps，超过 1.5 dps 绝对阈值会永远判不静止；零偏幅值交由 5 dps 门把关。代价：3 s 内匀速慢转无法与零偏区分，会被吸收为零偏。

手持阈值（2026-10-17 实机标定）：手持最稳的 3 s 窗口逐轴方差 0.5–1.0 dps²、偏离均值 1.5–2.1 dps，桌面静置为 0.001 dps² / 0.1 dps；明显晃动的窗口方差 ≥ 2 dps²、偏离 ≥ 3 dps。故偏离阈值取 3.0 dps、方差阈值取 1.5 dps²。复测：手持 3 次 `cal` 全部通过，用时 4.7 / 7.2 / 8.1 s，准星在 10 px 目标圈内偏差多为 1–2 px。代价：手持窗口内的缓慢漂动会被当成零偏，3 次实测偏航轴零偏误差 +0.24 / +0.06 / −0.00 dps，约 14 / 3.5 / 0.1°/分钟漂移，波动较大（桌面校准误差 ≤ 0.05 dps，约 ≤ 3°/分钟）；需要更稳时放在桌面上 `cal`。

转动/晃动只重启倒计时（`KEEP STILL`），不计失败次数；只有 3 s 窗口跑满后被校验门拒绝才计一次（`integrator.rejected`）。恢复性失败重复引导，最多 `CHART_MAX_GATE_RETRIES`（8）次；此后 `fatal=CHART_FATAL_GATE`，整屏变暗红底色并显示 `CAL FAILED`。IMU 未找到（WHO_AM_I 不是 0x68）显示 `IMU NOT FOUND`，I²C 故障显示 `IMU I2C FAULT`——均不可恢复，需串口 `cal` 重试或断电检查接线。

偏航率公式为 `ψ̇ = dot(ω − bias, â)`，其中 `â` 是单位重力矢量（机体坐标系）。这是数学恒等式（数值验证 5 万随机姿态，误差 < 1.4e-15 rad/s），对任意倾角成立，因此 `CHART_IMU_YAW_AXIS` 已删除，安装方向不再需要配置；`CHART_IMU_YAW_SIGN=-1`（2026-10-17 实机确认：芯片正面朝上，从上方看顺时针为正；曾误把黄色峰值标记的行为当成方向反了而翻成 +1，已改回）。串口 `imu` 命令转储原始陀螺/加速度和投影后的偏航率，用于实机确认符号：水平顺时针转，`stats heading` 应为正且旧 0° 点向左；符号反了改 `CHART_IMU_YAW_SIGN` 重新烧录。

校准后不使用大死区，0.2°/s 等慢转动仍积分。不采用 DMP/加速度消除 yaw 漂移，不用 RSSI 强峰校正偏航，也没有自动静止偏置追踪，避免误抹慢转动。需测 60 秒静置漂移并记录起止角，漂移累积时 `zero` 或 `cal`；设备不是绝对指南针。

## Wi-Fi 锁定

在集中配置填写 `CHART_TARGET_SSID`，可选 `CHART_TARGET_BSSID`。默认空 SSID 在真实模式明确报错，不把演示名 CAM_02 当实际 AP。国家码 `CHART_WIFI_COUNTRY` 必须符合实际地区。

启动真实模式只扫描一次，选择指定 BSSID，或同名 SSID 中最强的一项。串口输出候选和最终 `LOCK aa:bb:... CHn MHz`，之后不自动换 AP、不全频段循环扫描，也不要求密码或关联。C5 使用对应 2.4/5 GHz 模式和主信道，含 CH14 特例，合法 5 GHz 中心频率按真实信道计算。

回调过滤管理帧、Beacon 子类型、最小帧长、错误接收、DS 标志及 transmitter/BSSID 两个地址。只收这个 AP 的 Beacon，不是 AP 下客户端或摄像头的 RSSI。回调不处理统计、不画屏，有界队列满则丢包并统计。

目标关闭超过两秒：保留历史，顶部值变灰，提示「等待信号」，趋势按原始时间滚出而非新增假数据。相同 BSSID 在相同频道恢复后继续。目标换频道不会自动跟踪，需要明确重新 `mode live` 扫描；启动未发现也需明确重试。注意真实 RSSI 受多径、遮挡、姿态和自动增益影响，峰值不是精确方向或距离。

字库已嵌入 10/12/18/24 px、4-bit 精简 Noto Sans SC，共 384 个字形、30263 B 位图数据，许可见 `fonts/OFL.txt`。盒高由字体自身 ascent/descent 决定并按各字号实际墨迹统一裁剪，`top` 字段让不同字号共享基线；数字按字号等宽，读数变化不挤动相邻文字。24 px 仅含数字与正负号，供 RSSI 读数使用。包含本页中文状态、ASCII 和度数；不支持任意中文 SSID，未包含字符显示 `?`，长名称省略。重建字库可从 Google Fonts `ofl/notosanssc/NotoSansSC[wght].ttf` 获取源字体后运行 `tools/generate_chart_font.py <font> include/starchart_font.h`；源字体约 17 MB，不随仓库提交，烘焙后的头文件才是交付物。生成器遇到非空格字形烘焙为空白会直接报错，`tools/inspect_chart_font.py` 可复核墨迹边界。数字不依赖运行机器字体。
