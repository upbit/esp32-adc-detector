# 信源星盘 V1 原型

下一版参见 [UI 还原需求与实施计划](starchart-ui-reconstruction-plan.md)：已确认大星盘与差异刷新方向，本轮只整理计划，具体设计待确认，代码及下述现行实现未改变。

2026-10-14 当前默认以 [LCD 刷新策略 14](lcd-refresh-test.md) 为新基线，临时屏蔽本文星盘任务及 5 秒检查页；动态面积 320×128，BOOT 顺序为 14→15（同算法 O2 热路径）→10（旧基线）→13（连续窗口同步）→14。初始化/命令为 40 MHz，像素为 80 MHz，保留每秒 FPS 更新和日志。`CHART_LCD_REFRESH_TEST=0` 恢复本文流程。下述“单 16 行缓冲”描述的是星盘模式；刷新测试仅分配 40 KiB，10/13 用单 64 行区，14/15 分成两个 32 行区，DMA 完成回收后才复用。

后续优化仅作 [真实 UI 阶段备忘](lcd-refresh-pipeline-design.md#真实-ui-阶段备忘暂不实施)：窗口缓存 + 跨帧首块预生成，以及更激进的跨帧持续窗口 + 持续流水线。用户决定暂不开发，到真实 UI 实测绘制、刷新区域、IMU/Wi-Fi 负载和帧间隔后再决策；实施前仍需设计及确认。

## 范围与设计依据

本实现依据 `星盘UI_V1_AI实现要求.md` 的第 3、4、5、6、7 节及 `UI_Design.png` 中间页面，不新增列表、BLE、距离、自动航向修正或按钮。仓库没有独立 UML 文件；要求文档中的采集、回调入队、应用统计、一致快照绘制约束是本轮行为设计依据。

| 文件 | 责任 |
|---|---|
| `include/starchart_config.h` | 已知接线、待确认屏幕参数、IMU 轴、AP、模式和视觉参数 |
| `src/chart_hardware.c` | ST7796 SPI、MPU6050 I2C、Wi-Fi 扫描与 Beacon 回调 |
| `src/starchart.c` | 连续角度积分、姿态历史插值、桶中位数、单峰、覆盖与重置 |
| `src/starchart_render.c` | 纯 RGB565 分块绘制，与主机预览完全共用 |
| `src/main.c` | 独立姿态、统计、显示、串口任务及有界队列 |

姿态约 100 Hz，Wi-Fi 回调入口使用 `esp_timer_get_time()`，等待下一条姿态观测后按事件时间插值；绝不采用显示缓动角度写入方向桶。超出历史、跨越采集停顿或旧坐标系的事件被拒绝。日志 `event_age_max` 表示入口到应用处理的最大年龄，`data_age` 是最新有效包年龄。这是软件事件时间对齐，不是射频硬件同步。

桶内只存该方向最近五包的 RSSI、采样角度、中位数、累计包数与最新时间。强峰至少三包确认，切换需超出可配置滞回。36 桶表示覆盖分辨率，不是方向精度。RSSI 只改变固定 R=88 上的亮度与厚度。仅相邻已采样桶连弧，空白桶不会填满。渲染时间只改变历史颜色与线宽，不改保存 RSSI。

## 编译和烧录

工具链：PlatformIO Core、pioarduino `55.03.312-1`、ESP-IDF 5.5.5、RISC-V GCC 14.2.0。保持 16 MB Flash、DIO 40 MHz、USB Serial/JTAG；不假设有 PSRAM。

```sh
export PATH="$HOME/.platformio/penv/bin:$PATH"
pio run
pio device list
pio run -t upload --upload-port /dev/cu.usbmodem101
pio device monitor --port /dev/cu.usbmodem101
```

端口以当前 `pio device list` 为准。2026-10-13 按用户请求烧录黑屏排查固件到 `/dev/cu.usbmodem1101`，写入哈希校验通过；未执行整片擦除或 NVS 擦除。

## 接线与屏幕确认

沿用 README：屏幕左侧 MOSI=8、SCK=6、CS=10、DC=9；MPU6050 右侧 SDA=23、SCL=24，AD0 接地、地址 0x68，VCC 共用 3V3，INT 不使用。核对实际开发板和模块输入电压；I2C 推荐模块已有或外接适当上拉，不依赖弱内部上拉实现高速通信。

用户已确认屏幕接线，BL 已连接 GPIO0；按本轮要求不调整背光，`CHART_LCD_BL=-1` 仍不驱动，未标记引脚不使用。不能把 GPIO 当 LED 电源。

ST7796 目前采用软件复位、退出睡眠、RGB565、MADCTL、反色、开显示的保守 DCS 初始化候选序列。**尚未取得 TK015F4000 转接板厂商电源/gamma 初始化表，也未确认可见窗口偏移，不宣称实机可直接显示。** 若上电只有背光/白屏，取得模块初始化表并在 `chart_lcd_init()` 对照替换，不擅用其他屏控制器。

当前显示调试配置：SPI 恢复 40 MHz，启动检查图保持 5 秒后进入星盘，`CHART_LCD_MIRROR_X=1` 校正用户报告的左右镜像。检查图逻辑顺序从左到右为铺满全高的红、绿、蓝、白色条，四边黑色 1 px 边界，四角 TL/TR/BL/BR，中央数字与中文；不反转渲染器像素或修改 RGB/BGR。保持期间 `health fps=0` 是预期行为，不表示显示任务失败。串口输出接线参数、BL 未驱动提示、MADCTL，以及 `test pattern sent over SPI`；后者只说明发送成功，没有屏幕应答或光学确认。检查步骤：

1. 核对供电、SPI 接线；无独立 RESET，先使用软件复位。
2. 确认四边完整，配置 `CHART_LCD_X_OFFSET/Y_OFFSET`，当前 0/0 仅为待验证初值。发送窗口始终严格 320x320，不做 320x480 拉伸。
3. 红蓝互换时切换 `CHART_LCD_BGR`；异常底色检查 `CHART_LCD_INVERT`。
4. 左右镜像检查 `CHART_LCD_MIRROR_X`；旋转方向错误时调整 `CHART_LCD_ROTATION`，并重新测偏移。
5. 排查信号完整性时可降 `CHART_LCD_SPI_HZ`。实际流畅度以 `health fps` 与目视撕裂检查为准。

只有一个 16 行 DMA RGB565 缓冲（10240 B）与模型快照，逐块在内存完整绘制后写入屏幕；不会先清可见屏再逐条绘图，也不分配整屏双缓冲。模型在主机 ABI 下 7256 B，设备 ABI 可能不同。目标 25 FPS，但分块全屏传输与 CPU 光栅化耗时尚未实测，不能保证达到目标或无撕裂。每帧无动态分配；姿态、趋势和命令队列都有容量上限。

SPI 总线原先已启用 `SPI_DMA_CH_AUTO`，本轮将长像素事务从 `spi_device_polling_transmit()` 改为 `spi_device_transmit()`，使用中断完成的 DMA，并等待结果后复用缓冲。1～4 字节命令/参数放入事务内联数据并轮询发送，避免短事务临时 DMA 缓冲；不混用尚未完成的轮询/中断事务，不新增异步缓冲或修改显示任务结构。每约 5 秒输出 `lcd: perf` 的完整帧率、平均绘制/传输墙钟耗时和最大帧工作时间；传输统计包含字节交换、窗口命令和等待，墙钟统计包含调度抢占。40 MHz 下 204800 字节像素数据需至少 40.96 ms，理想传输上限约 24.4 FPS，不代表实际 UI 帧率。

## 模式与串口

串口输入一行命令后发送换行，`help` 显示完整帮助。

| 命令 | 行为 |
|---|---|
| `mode ui` | UI_SIM：不初始化 MPU6050/Wi-Fi，默认 15°/s 自动转，100 ms 合成一包 |
| `mode imu` | IMU_SIM_RSSI：真实 MPU6050，合成信号固定峰 +60° |
| `mode live` | LIVE_WIFI：真实 MPU6050、一次扫描确定 BSSID、固定频段频道接收 Beacon |
| `angle 30` | 仅 UI_SIM，输入归一角，通过最短变化展开成连续角度，关闭自动旋转 |
| `auto on` / `auto off` | 开关 UI_SIM 自动旋转 |
| `signal on` / `signal off` | 开关合成包；对 LIVE_WIFI 无效，不伪造真实读数 |
| `clear` | 清历史、峰值、RSSI 窗口、趋势、进度，保留相对朝向 |
| `zero` | 同步清空并设当前朝向为 0°，保留已估计陀螺零偏 |
| `cal` | 重试 IMU 初始化，清空，重新静置校准；UI_SIM 中等同置零 |
| `stats` | 测量/显示角度、倾斜、桶数、包数、对齐拒绝与延迟 |

模式切换和重校准会清空本轮，不保留跨坐标系数据。真实/合成事件带来源标记，旧队列数据不能混入新模式。真实 IMU 失败显示「IMU 错误」，不会悄悄模拟。校准或长采集停顿时显示「静置校准」，停顿后重校准以避免未知 dt 误积分。

## IMU 调试

`mode imu` 后水平静置约 2.5 秒。检测陀螺绝对值、加速度幅值、倾斜与校准窗口陀螺方差；明显转动重启静置窗口。校准检测不是额外航向参考，匀速极慢转动仍可能难以区别于零偏，务必静置。校准后不使用大死区，0.2°/s 等慢转动仍积分。

`CHART_IMU_YAW_AXIS=2`、`CHART_IMU_YAW_SIGN=-1` 只是可配置的安装初值，未完成传感器物理方向确认。水平从上方顺时针转 30°，`stats heading` 应为约 +30°，旧 0° 点向左约 30°；反号则修改符号，安装轴不同则修改轴与水平轴。转到约 +60°，模拟最强约 -50 dBm 且记录强峰靠近顶部。

明显倾斜显示「保持水平」。不采用 DMP/加速度消除 yaw 漂移，不用 RSSI 强峰校正偏航，也没有自动静止偏置追踪，避免误抹慢转动。需测 60 秒静置漂移并记录起止角，漂移累积时 `zero` 或 `cal`；设备不是绝对指南针。

## Wi-Fi 锁定

在集中配置填写 `CHART_TARGET_SSID`，可选 `CHART_TARGET_BSSID`。默认空 SSID 在真实模式明确报错，不把演示名 CAM_02 当实际 AP。国家码 `CHART_WIFI_COUNTRY` 必须符合实际地区。

启动真实模式只扫描一次，选择指定 BSSID，或同名 SSID 中最强的一项。串口输出候选和最终 `LOCK aa:bb:... CHn MHz`，之后不自动换 AP、不全频段循环扫描，也不要求密码或关联。C5 使用对应 2.4/5 GHz 模式和主信道，含 CH14 特例，合法 5 GHz 中心频率按真实信道计算。

回调过滤管理帧、Beacon 子类型、最小帧长、错误接收、DS 标志及 transmitter/BSSID 两个地址。只收这个 AP 的 Beacon，不是 AP 下客户端或摄像头的 RSSI。回调不处理统计、不画屏，有界队列满则丢包并统计。

目标关闭超过两秒：保留历史，顶部值变灰，提示「等待信号」，趋势按原始时间滚出而非新增假数据。相同 BSSID 在相同频道恢复后继续。目标换频道不会自动跟踪，需要明确重新 `mode live` 扫描；启动未发现也需明确重试。注意真实 RSSI 受多径、遮挡、姿态和自动增益影响，峰值不是精确方向或距离。

## 预览与测试

```sh
sh tools/test_chart.sh
python3 -m pip install Pillow
python3 tools/build_chart_preview.py
```

测试使用 C11、`-Wall -Wextra -Werror`、AddressSanitizer、UndefinedBehaviorSanitizer。预览工具编译固件同一统计/绘制代码，以 320x320 原生 RGB565 输出 PNG/GIF，不使用网页或系统字体替代设备 UI。脚本仅预览需要 Pillow；固件编译不需要 Python 字体环境。

动画真实生成合成包，扫描 -40° 至 +70° 后停止生成，继续反向转动；覆盖 12/36，111 包，最终稳定峰约 +62°（10° 桶和窗口统计造成的近似），不是预先画好的完整圈。图片为模拟输出，不是设备测量记录。

字库已嵌入 10/12/18/24 px、4-bit 精简 Noto Sans SC，共 384 个字形、30263 B 位图数据，许可见 `fonts/OFL.txt`。盒高由字体自身 ascent/descent 决定并按各字号实际墨迹统一裁剪，`top` 字段让不同字号共享基线；数字按字号等宽，读数变化不挤动相邻文字。24 px 仅含数字与正负号，供 RSSI 读数使用。包含本页中文状态、ASCII 和度数；不支持任意中文 SSID，未包含字符显示 `?`，长名称省略。重建字库可从 Google Fonts `ofl/notosanssc/NotoSansSC[wght].ttf` 获取源字体后运行 `tools/generate_chart_font.py <font> include/starchart_font.h`；源字体约 17 MB，不随仓库提交，烘焙后的头文件才是交付物。生成器遇到非空格字形烘焙为空白会直接报错，`tools/inspect_chart_font.py` 可复核墨迹边界。数字不依赖运行机器字体。

## 本轮实际结论

| 项目 | 结论 |
|---|---|
| 默认 UI_SIM 固件编译 | 通过 ESP-IDF 5.5.5 / ESP32-C5 链接与镜像生成 |
| 非空测试 SSID 编译 | 通过；确保真实 Wi-Fi 分支与驱动链接，不仅测试空配置早退 |
| 坐标与跨界 | 通过 0° 顶部、+30° 旧点向左、新点顶部、±180° 连续 |
| 同步与容器 | 通过连续展开插值、不外推、过期/停顿拒绝、有界历史 |
| 覆盖与峰值 | 通过原地不增加覆盖、单包尖峰不夺峰、至少三包确认 |
| 校准 | 通过明显转动延后、静置零偏、保留慢转动、长停顿重校准的软件测试 |
| Beacon 过滤 | 通过短帧、非 Beacon、DS、错误 transmitter/BSSID 的主机测试；未接射频 |
| 渲染与渐隐 | 通过原生栅格、空白方向、渲染不修改 RSSI、老化变色的软件测试 |
| 十分钟模拟时间 | 通过 60000 姿态点、6000 包、36/36 覆盖，有界容器；不是十分钟实机运行 |
| 视觉比对 | 已用图像查看器对照概念中间页和最终 PNG：布局、色板、嵌入字体、固定天线、单峰、进度、状态无明显重叠；删除外部边框/标题，加入要求中的「模拟」标记 |
| 实机验收 | 2026-10-13 已烧录黑屏排查固件并读取启动日志；10 MHz SPI 测试图发送成功，BL 未驱动，可见效果待用户确认。此前固件串口约 0.40 FPS；IMU/Wi-Fi/漂移和十分钟稳定性仍待验证 |

非空测试 SSID 编译镜像约 976 KB，链接报告 HP SRAM 约 156 KB（包含驻留代码）。这与运行时堆内存不是同一指标。默认空 SSID 编译器可能裁去不可达 Wi-Fi 初始化路径，不能用默认镜像大小估算真实模式资源。

实机十分钟记录每五秒 `health` 的 FPS、当前/最低堆、队列、丢包、包数、同步拒绝、数据年龄与相对角度，并记录屏幕闪烁/撕裂和 60 秒静止漂移。未取得数据前，不填造实测指标，不宣称完整硬件验收通过。
