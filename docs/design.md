# ESP32-S3 + AD8318 隐藏发射设备探测器 — 方案说明

> 状态：方案已确认；主控板换为 Waveshare ESP32-S3-RLCD-4.2，AD8318 未到货，开发顺序待调整。最后更新：2026-10-04

## 1. 目标与场景

- **目标**：在室内手持扫描，找出**正在发射射频信号**的隐藏设备（Wi-Fi 摄像头、BLE 追踪器、GSM 窃听器等）。
- **场景**：酒店、民宿等地点的**临时检查**，便携使用，单次不超过 30 分钟。
- **不在范围内**：不发射信号的设备，例如只录本地存储的摄像头。

### 2.3 AD8318 检波器

| 项 | 规格 / 接线 |
|---|---|
| 频率范围 | 1 MHz–8 GHz，对数检波 |
| 输出特性 | **0.5 V–2.1 V，信号越强电压越低**，约 −25 mV/dB |
| 输出接线 | 中心触点接 **GPIO1**（排针 GP1，ADC1_CH0），屏蔽层接 GND。原计划的 GPIO4 在本板上被 BAT_ADC 占用 |
| ADC 设置 | ESP-IDF `ADC_ATTEN_DB_12`（等同 Arduino 的 `ADC_11db`，量程约 0–3.1 V，能覆盖输出范围） |
| 供电 | 5V。排针 VBUS 很可能只在插 USB 时有 5V，电池供电时需要另加 5V 升压模块（见下方待确认） |

### 2.4 待确认 / 注意

- **AD8318 的 5V 从哪来**：拔掉 USB、只用 18650 开机，量排针 VBUS 电压。没有 5V 就要加升压模块，升压的开关噪声可能干扰测量，需要选低噪声型号并加滤波。
- ~~**GPIO48 LED**~~：已处理（2026-10-04）。本板没有用户 LED（GPIO 表里没有 GPIO47/48），原计划的 LED 闪烁反馈统一改由 RLCD 显示，§3.4、§4、§7、§8 已同步修改。
- ~~**屏幕驱动芯片和触摸**~~：已确认（2026-10-04）。驱动 IC 是 ST7305，单色 1bpp；官方示例都没用触摸，TP 引脚空闲。见 §6.1。
- ~~**PlatformIO 的 IDF 版本**~~：已确认。PlatformIO espressif32 7.0.1 自带 IDF 6.0.1，满足要求。
- **音频功放自干扰**：如果用扬声器做反馈，功放和 I2S 时钟可能耦合进 AD8318 读数，需要实测。
- 部分 AD8318 模块输出端的滤波电容较大，会把突发信号抹平，影响 P2 分类。AD8318 到货后需要实测上升时间。
- 电源：18650 供电，单次 30 分钟，续航不是瓶颈，可以全速采样、不做低功耗。

## 3. 核心算法：多轮探测 + 突变识别 + 追踪

### 3.1 为什么不能只做"背景减除"

如果背景学习时房间里已有设备在持续发射（例如摄像头一直在推流），它就会被算进背景，再拿"当前值 − 背景"判断时就**被忽略了**。

两个对策一起用：**双通道检测**（§3.2），以及在**断电状态下采集背景**（§3.3）。

### 3.2 改进方案：双通道检测

| 通道 | 参照基准 | 能发现什么 |
|---|---|---|
| **A. 突变通道** | 短时滚动基线（过去几秒的统计） | 信号**突然出现或变化**：设备开始传输、靠近了间歇性发射源 |
| **B. 电平 / 空间梯度通道** | **全程最安静区域的噪底**（各区域噪底中的最小值），不是房间均值 | **持续发射**的设备：持续发射源离得越近读数越高（约按距离平方衰减），对比最安静的点就能显出来 |

要点：
- **基准取低分位数**（如 P10），不取均值或峰值。持续发射源只抬高它附近的区域，不会抬高"最安静点"的噪底。
- **同时保留绝对 dBm**：绝对电平本身很高的区域，即使变化不大也算可疑。
- **看空间梯度**：远处的路由器在整个房间里读数差不多平；近处的隐藏设备在约 1 m 内会有 10–20 dB 以上的落差。

### 3.3 断电基线 + 上电差异

"断电"指关掉房间市电（插卡取电或空气开关）。探测器用锂电池，不受影响。隐藏摄像头大多是市电供电的（插座、充电头、烟感、时钟），断电前后对比就能把它们分出来。

| 设备类型 | 断电时的 Wi-Fi/BLE 清单（P3） | 断电采背景、上电看差异（P1） |
|---|---|---|
| 市电供电的隐藏设备 | 不在清单里 | **上电后新出现**，差异最明显 |
| 电池供电的设备（AirTag、电池摄像头、GSM 窃听器） | **在清单里**，不会漏掉 | 断电后照常发射，看不出差异，靠 §3.2 空间梯度定位 |
| 邻居路由器、楼宇 AP | 在清单里，标为外部设备 | 断电前后都在，差异里自动去掉 |

**限制**
- 断电可能不彻底：插卡取电通常不断冰箱、部分插座和烟感回路。内置电池的摄像头断电后继续工作，按电池设备处理。
- 上电后电视、房间 AP 等正常设备也会出现。差异只是把范围缩小成短名单，还要结合位置（和 P3 的厂商信息）排除。
- 设备上电后 10–60 秒才开始传输。开机过程（探测请求、关联、开始推流）本身就是明显的突增，适合用突变通道抓。
- 扫描时自己的手机要开飞行模式。

### 3.4 探测流程

阶段切换靠手动：**长按 BOOT 键**确认"已断电"或"已上电"，**短按**标记区域。RLCD 显示当前阶段。

1. **开机自检**：采样约 3 秒，确认 ADC 读数在 0.5–2.1 V 之间。
2. **断电基线**（约 5 分钟）：断电后长按确认，按区域逐片普查，例如床头、电视、插座、烟感、空调、镜子，每到一个区域短按一下。每个区域记录 P10 噪底、峰值、占空比。各区域噪底的最小值作为全局基准，突出的区域先标为可疑（电池设备嫌疑）。
   - P3 起：普查前先做 Wi-Fi/BLE 被动扫描，记下设备清单（§6）。
3. **上电监视**（约 1–2 分钟）：上电后长按确认，站在房间中央，突变通道盯住开机时的突发。
   - P3 起：再做一次 Wi-Fi/BLE 清单，列出新出现的设备。
4. **上电复查**：按相同区域顺序重扫，和断电时逐区域对比。
   - 上电后明显升高 → 市电供电设备，高嫌疑
   - 断电、上电都高 → 持续发射源（电池设备或外部强信号，看空间梯度区分）
   - 有时高有时低 → 间歇发射源（休眠唤醒、按需传输）
5. **追踪模式**：选中一个可疑区域后进入。只看峰值保持和相对变化，RLCD 上用实时 dB 条和数值表示远近，用来精确定位。P3 起可以用目标设备的 RSSI 辅助判断远近。

### 3.5 采样与处理

- `adc_continuous` DMA 连续采样，默认 **40 kHz**，足够抓 GSM 577 µs 的突发。
- DMA 回调里只做最小 / 最大值和突发边沿检测，统计和判断放在低优先级任务里。
- 每 10–50 ms 出一个窗口统计：峰值（电压最小值）、P10、均值、超阈值占空比。
- 电压换 dBm：先用手册参数，之后支持两点校准，结果存 NVS。判断时主要用相对 dB。

## 5. 备忘：信号特征分类（P2）

靠突发长度直方图和周期自相关判断信号类型：

| 特征 | 推测 |
|---|---|
| 约 102.4 ms 周期的短突发 | Wi-Fi beacon（AP 或配网中的设备） |
| 长时间高占空比 | 持续推流视频，**高嫌疑** |
| 4.615 ms 周期 / 217 Hz | GSM：插卡窃听器或定位器 |
| 20 ms–数秒周期的极短突发 | BLE 广播：AirTag 类追踪器 |

## 6. 备忘：Wi-Fi / BLE 被动扫描（P3）

- 用 Wi-Fi promiscuous 模式（只接收、不发射）列出 AP 和终端设备的 MAC 与 RSSI；用 BLE 扫描列出广播设备。
- 按 MAC 前缀（OUI）查厂商，海康、大华、涂鸦、乐鑫模组等标为可疑。
- 和 AD8318 互补：AD8318 负责定位，扫描结果负责说明设备身份。
- **断电清单 + 上电差异**（配合 §3.3）：断电时扫一次作为基线，上电后再扫一次，新出现的设备是市电供电设备候选；断电清单里 RSSI 强、厂商可疑的是电池设备候选。
- **只支持 2.4 GHz**：ESP32-S3 扫不到只连 5 GHz 的设备，这类设备靠 AD8318 能量差异发现。
- **MAC 随机化**：BLE 设备（尤其 AirTag、手机）约 15 分钟换一次地址，Wi-Fi 探测请求也常用随机 MAC，直接比 MAC 列表会误判。对策：
  - 看"本地管理位"，随机地址单独归类（摄像头通常用固定厂商 MAC）。
  - 断电和上电两次扫描的间隔尽量短，几分钟内完成。
- **注意自干扰**：ESP32 自己的发射会把 AD8318 打满。必须只接收不发射，并且和 AD8318 测量分时进行。
- N16R8 的 16MB Flash 放得下这部分固件。

### 6.1 实现方案（2026-10-04 确认）

P1 还没做，P3 先作为**独立的扫描模式**运行，结果从串口输出。以后接入 §3.4 流程时，只需替换触发方式。

| 模块 | 文件 | 职责 |
|---|---|---|
| 主流程 | `src/main.c` | 初始化，BOOT / KEY 键和串口命令分轮，依次调用 Wi-Fi 扫描、BLE 扫描，输出报告 |
| 显示 | `src/rlcd.c/.h`，`src/ui.c/.h`，`src/fonts/` | RLCD 驱动、LVGL 界面、像素字体 |
| Wi-Fi 扫描 | `src/wifi_scan.c/.h` | `WIFI_MODE_NULL` + 混杂模式，1–13 信道每个停 250 ms，跳 2 遍（约 6.5 s）。国家码设为 CN |
| BLE 扫描 | `src/ble_scan.c/.h` | NimBLE，只开 Observer 角色；被动扫描（不发 scan request），扫 5 s，窗口等于间隔 |
| 设备表 | `src/devices.c/.h` | 按（类型, MAC）去重，记录本轮最强 RSSI、包数、信道、名称；保存基线并做差异 |
| 厂商表 | `src/oui.c/.h`，`tools/gen_oui.py` | 可疑厂商 OUI 表，用脚本生成 |

- **只收不发**：Wi-Fi 用 NULL 模式加混杂模式，BLE 用被动扫描。Wi-Fi 和 BLE 分时进行，Wi-Fi 跑完先 `esp_wifi_stop()` 再开始 BLE。
- **Wi-Fi 帧解析**（只看管理帧和数据帧）：
  - Beacon / Probe Response → AP，记录 BSSID、SSID、DS 参数里的信道
  - Probe Request → 终端 STA（多为随机 MAC）
  - 数据帧 ToDS → STA（addr2），同时记录它所属的 AP（addr1）
  - 数据帧 FromDS → AP（addr2）
  - 能看到"已连上房间路由器的摄像头"，就是靠数据帧 ToDS
- **随机地址**：Wi-Fi 看本地管理位（首字节 bit1）；BLE 看地址类型，random 类地址单独标出，不查 OUI。
- **交互**：按键和串口命令并存，都在主任务里处理。
  | 操作 | 按键 | 串口（USB Serial/JTAG，单字符） |
  |---|---|---|
  | 扫一轮。第 1 轮保存为基线（断电时扫）；之后每轮标出 `NEW`（基线里没有）和 `GONE`（基线里有、本轮没扫到） | **BOOT 短按**（GPIO0，50 ms–1 s） | `s` |
  | 清空基线，下一轮重新作为基线 | **BOOT 长按 ≥1 s**（松开时生效） | `c` |
  | 翻页：先翻完当前类型的各页，再切到下一类型，顺序为 AP → STA → BLE → AP | **KEY**（GPIO18） | `p` |
  - 扫描约 12 s，期间不响应按键（主任务阻塞在扫描里）。
  - 控制台从 UART0 改为 USB Serial/JTAG，因为串口命令需要能输入。
- **RLCD 显示**（`src/rlcd.c`、`src/ui.c`，调试阶段用来看状态）：
  - 驱动 IC 是 ST7305，单色 1bpp，横屏 400×300。SPI3 跑 10 MHz，初始化序列照搬官方示例 `09_LVGL_V9_Test`。
  - LVGL 9.4 按 L8 格式整屏渲染，flush 时按阈值（见下方字体一节）转成 1bpp 后整屏发送。LVGL 在独立任务里跑，其他任务改界面前要先 `lv_lock()`。
  - 界面布局：顶部是状态栏，第二行是本页统计和 NEW / GONE 数，下面是设备表，每页一种类型，一页最多约 22 行；一种类型放不下时分几页，统计行显示该类型的页码，例如 `[AP 2/3]`。表格按 NEW → 信号强度 → GONE 排序。名称列：AP 显示 SSID，STA 显示所属 AP 的 SSID，BLE 显示广播名；没有名称时显示 MAC。
  - **字体（2026-10-04 实机对比后确定）**：屏幕没有灰阶，抗锯齿字体（如 LVGL 自带的思源黑体 4bpp）经阈值二值化后，14 px 汉字的细笔画会断开，例如"不"字残缺。所以改用像素字体，1bpp 显示不失真：
    - **小字**：Fusion Pixel 10px（`font_fusion10`），行高 10。用于表格、统计行，一屏约 23 行。
    - **大字**：Ark Pixel 12px（`font_ark12`），行高 12。用于状态栏、标题。
    - Fusion Pixel 12px 也可用，实测效果正常，备选。
    - 字符集：ASCII + GB2312 6763 字 + 常用中文标点，1bpp。用 `tools/gen_fonts.py` 生成到 `src/fonts/`，需要 `npx lv_font_conv`。字体来源 github.com/TakWolf/fusion-pixel-font 和 ark-pixel-font，许可为 OFL，见 `docs/fonts/`。
    - L8 转 1bpp 的阈值是 192（`rlcd.c`）。像素字体只有纯黑和纯白，阈值对它没有影响；阈值只影响其他抗锯齿元素。
- **BLE 扫描时长**：只开 Observer 角色时，NimBLE 的 host 定时器不处理 GAP 超时（相关代码在 `NIMBLE_BLE_CONNECT` 宏里），带时长的扫描不会自己结束，也收不到 `DISC_COMPLETE`。改为以 `BLE_HS_FOREVER` 开始扫描，等 5 s 后调用 `ble_gap_disc_cancel()`。
- **报告**：按类型分组，组内按 RSSI 从强到弱排序。每行显示：MAC、信道、RSSI、包数、厂商（仅可疑厂商）、随机标记、SSID 或 BLE 名称、STA 所属 AP。
- **设备表**：静态数组，上限 512 条。表满后丢弃新设备并计数。不在基线里、本轮也没扫到的条目，在每轮结束时清掉。
- **OUI 表**：IEEE 官网下载被拒，改用 Wireshark `manuf`（同样来自 IEEE 分配数据）。只收 24 位 MA-L 前缀，厂商包括海康、萤石、大华、宇视、涂鸦、乐鑫、小米、AltoBeam、必联、博流、博通集成（Beken）、Wyze、Arlo、Reolink、SigmaStar、君正。重新生成：`python3 tools/gen_oui.py`。
